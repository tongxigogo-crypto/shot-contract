# 分镜契约（shot-contract）

给 AI 视频分镜用的一套**可校验契约**。它不生成视频，它阻止分镜写成一堆形容词让模型去猜。

> 英文是主文档（[README.md](README.md)）。本页只做中文导读。

## 它拦的五种失败

| 现场 | 分镜里缺的是 |
| --- | --- |
| 镜头在飘，不知道该在哪剪 | 没有时间码、没有 beat 结构 |
| 人物最后都跑到同一侧 | 两个人之间没有轴线 |
| 镜头无缘无故地动 | 运镜没有画面内的触发点 |
| 脸变形、多出人、墙上长出招牌 | 没有负向约束 |
| 看着挺贵，但什么也没说 | purpose 是个形容词 |

## 校验什么

| 规则 | 为什么 |
| --- | --- |
| 每镜引 1–2 条规则（默认上限 2） | 十秒的生成塞三个机位想法，模型会三个都妥协 |
| `purpose` 不许用「电影感 / 高级感 / 大气 / cinematic / epic」 | 形容词没法执行 |
| 单镜时长默认 3–15 秒 | 超出窗口，AI 镜头就撑不住连贯性 |
| `negative` 至少一条 | 你不写，模型就自己发明 |
| 有台词必须声明两人 `spatial.axis` | 最常见的可避免事故就是切的时候跳轴 |
| 三人及以上必须有 `topDownMap` | 在提示词里决定空间，等于决定得太晚 |
| `ruleRefs` 必须能在规则库里解析到 | 引用不存在的规则，等于这镜没有空间设定 |
| 相邻镜头轴反转、时间断裂、内容无时间码、运镜无动机 → 警告 | 警告是要人签字的决定，不是静默通过 |

错误阻断拍摄，警告打印并计数。

## 规则库是你的，仓库不提供

本仓库只放**格式和工具**，不含规则库。从书、付费课、别人的笔记里整理出来的库，一律不收。

```json
{
  "schemaVersion": "0.1",
  "source": { "kind": "original", "note": "..." },
  "rules": [
    { "id": "OTS-1", "title": "…", "purpose": "…", "conditions": "…", "risk": "…" }
  ]
}
```

`source.kind` 三选一：`original` / `licensed` / `local-import`。

`local-import`（私用但不许再分发）必须写 `note` 说明来源，并且**不能进仓库**：

```gitignore
rules.local.json
*.corpus.json
```

`--rules` 读任意路径，所以私有库和提交进仓库的库用法完全一样。

`references/rule-library-format.md` 讲清了「可发布的镜头语法」和「他人受保护的取舍与措辞」之间的界线。

## 快速开始

```sh
npm test                    # 20 个契约测试，无需安装依赖
npm run validate:examples
node src/cli.mjs validate --file your/storyboard.json --rules your/rules.json
```

## 诚实范围（0.1.0）

- 校验器与测试已实现，Node 20 / 22 通过 20 个测试。
- 这套契约在一个短视频工作流里用过；项目私有，所以本仓库不引用无法核验的数字。
- `examples/` 里那 4 条规则是为本仓库写的格式样例，不是从任何出版物抄的。
- 没有渲染器集成，也没有「提示词直接出片」的 runner。产出物是一份通过校验的分镜表，任何工具都能接。
